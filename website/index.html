Keep the whole file.
Send what’s new.

When you change a dataset, update a model or rebuild an artifact, some of its contents may stay the same. openxet gives those parts a second use.

  1. 1

    Find the parts

    The upload tool splits your file into small pieces, called chunks, and identifies each one by its contents.

  2. 2

    Reuse what’s there

    It checks which chunks are already stored. Matching chunks can be reused, even across different files.

  3. 3

    Upload the new pieces

    Only new chunks need uploading. When you download, the pieces come back together as your complete file.

This is deduplication, using the Xet protocol developed by Hugging Face. Read how Xet works ↗

A few practical
questions.

Looking for a technical detail?
Start with the documentation.

Is this only for AI models?

No. openxet stores large files. Models and datasets are common examples, but build artifacts and other versioned files fit too. The benefit depends on how much content your uploads share.

How much will I save?

That depends on the files. If many chunks already exist in storage, less new data needs uploading. If everything is new, all those chunks need uploading. Compression, file formats and local caches also affect the result.

The diagram above explains reuse; it is not a benchmark or a prediction of your bill.

Is openxet part of Hugging Face?

No. openxet is an independent open-source project implementing the Xet protocol developed by Hugging Face. It is not affiliated with or endorsed by Hugging Face.

Can I use it today?

You can build the storage-only server and client from source and follow the tested quickstart. There is no packaged release yet. The Hub and Git layers and hosted service are planned.

What will the hosted service cost?

Pricing, limits and hosting locations will be published before launch. Join the waitlist if you’d like an email when hosted openxet is ready to try. Joining does not create an account or require payment.
